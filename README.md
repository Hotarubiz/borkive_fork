# 봇카이브 개인개조용

리스(RisuAI)에 다 넣어 두기 버거운 봇을 **파일로 꽂아 두는 내 서재**예요.
봇마다 카드 파일, 소개글, 채팅 로그, 모듈 같은 자료, 링크, 메모를 한곳에 모아 둬요.

[원본 봇카이브](https://github.com/redarchive77-coder/botkive)에 두 가지를 더했어요.

- NAS(Synology Container Manager)·Portainer에서 화면만 눌러 설치하기
- PocketRisu에서 [플러그인](https://github.com/Hotarubiz/botkive-risu-Link-plugin)으로 캐릭터를 골라 서재에 등록하기

> 혼자 쓰는 앱이에요. 내 컴퓨터나 내 기기끼리만 열어 두세요. 비밀번호 잠금을 켤 수 있지만 기본은 꺼져 있고, 잠가도 인터넷에 공개하는 건 권하지 않아요.

## 무엇을 할 수 있나요

- **봇 꽂기:** 리스에서 내보낸 카드(.charx · .png · .jpeg · .json)를 넣거나 리스 랠름 주소를 붙여 넣으면 이름·표지·로어북 수를 읽어 와요.
- **PocketRisu에서 등록:** 플러그인에서 캐릭터를 골라 보내면 카드·에셋·폴더까지 서재에 들어와요. 수백 개도 차례로 보낼 수 있어요.
- **버전:** 업데이트마다 카드·모듈·소개글을 한 묶음으로 남겨요.
- **소개글:** 아카라이브 글 주소로 가져오거나(그림까지 보관) 붙여 넣어요. 한 봇에 여러 개를 둘 수 있어요.
- **채팅 로그:** 리스에서 내보낸 채팅(.json · .jsonl)을 책처럼 읽어요. 시리즈로 묶기, 화 번호 정하기, 장면 표시(메모·그림)를 할 수 있어요. 카드의 표시용 정규식을 읽어서 에셋 그림도 보여 줘요.
- **그림 탭:** 봇마다 채팅하면서 만든 그림을 모아 둬요(끌어 놓기 · 붙여넣기). 그림마다 어느 채팅 · 몇 번째 메시지에서 나왔는지 이어 두면, 크게 볼 때 '채팅 열기'로 그 메시지까지 바로 가요. 표시한 장면에 붙인 그림도 같이 보이고, 채팅별로 거르거나 봇 표지로 쓸 수 있어요.
- **들여다보기:** 카드·모듈 속 로어북과 에셋을 리스 없이 봐요.
- **정리:** 폴더, 상태(하는 중·찜·끝 + 직접 더하기), 태그, 검색, 정렬, 카드 크기를 쓸 수 있어요. 폴더가 없는 봇은 `받은 봇` 폴더에 들어가요(폴더째 들인 봇은 **정리 전**에서 정리를 끝낸 뒤). **여러 개 선택**으로 폴더·제작자를 한 번에 바꾸거나 고른 봇을 한 번에 지울 수 있어요.
- **자료함:** 모듈·프리셋·로어북·플러그인을 봇처럼 카드로 모아요. 종류도 직접 더할 수 있어요.
- **페르소나:** 채팅할 때 쓰는 '나'를 그림 한 장 + 프롬프트 + 메모로 모아 둬요. 같은 사람의 여러 버전(탐험가용 · 헌터물…)은 한 폴더에 모이고, 폴더 페이지에서 버전마다 탭으로 넘겨 봐요. 표지를 누르면 그 버전 그림만 바로 바꿀 수 있고(끌어 놓기 · 붙여넣기 · 다른 버전 그림 쓰기), 버전을 그림 · 모듈까지 통째로 복제할 수도 있어요. 버전마다 프롬프트 · 자료실 · 로어북 · 에셋(자료실 모듈 속) · 갤러리 탭이 있고, 갤러리에는 그림을 마음대로 올려 두고(버전 전용 또는 폴더 공통) 메모를 달거나 버전 그림으로 쓸 수 있어요. 폴더마다 분류(기본 남캐 · 여캐, 설정에서 더하기)를 정해 위 칸으로 거를 수 있어요. 자료실은 봇 자료실처럼 버전 자료와 폴더 공통 자료로 나눠 모듈 · 프리셋 · 무엇이든 여러 개 넣어 둘 수 있어요. 리스에서 내보낸 페르소나 PNG를 넣으면 이름·프롬프트를 알아서 읽고, 리스용 PNG로 다시 내려받을 수도 있어요. 채팅 로그마다 페르소나를 고를 수 있고, 봇에 기본 페르소나를 정해 두면 새로 올리는 로그에 알아서 붙어요.
- **그림체:** 그림 생성용 프롬프트(작가·스타일 태그)를 견본 그림과 함께 모아 두고 버튼 하나로 복사해요. NAI·웹UI로 뽑은 PNG를 넣으면 프롬프트·설정을 알아서 읽어요. 흑백 · 채색 진하게 같은 변형을 탭으로 나눠 두고(변형마다 프롬프트 · 견본 그림), 갤러리에 그림을 마음대로 모아 둘 수 있어요(NAI 그림이면 프롬프트도 같이 읽음). 봇과 이어 둘 수 있고(공식·어울림), 파일(`.botkive-style.json`)로 내보내서 나눠 줄 수 있어요(갤러리는 빼고).
- **설정**(왼쪽 아래 톱니, 홈에서는 위쪽): 테마·글꼴, 상태·종류·분류 이름표, 내보내기·들이기, 잠금을 한곳에 모았어요.
- 자료는 **하루 한 번 자동 백업**돼요(30일치). 필요하면 **비밀번호 잠금**도 걸 수 있어요(끔 · 밖에서만 · 항상).

## 설치

아래 방법 중 **하나만** 따라 하면 돼요.

| 내 환경 | 방법 |
|---|---|
| Synology NAS | [Container Manager](#synology-container-manager) |
| Portainer | [Portainer](#portainer) |
| 도커가 깔린 컴퓨터 | [도커](#도커) |
| 도커 없이 컴퓨터에서 | [파이썬](#파이썬) (PocketRisu 연동은 안 돼요) |
| 코딩 LLM에게 맡기기 | [LLM에게 맡기기](#llm에게-맡기기) |

아래의 `192.168.0.10`, `botkive.example.com`, `/volume1/docker/botkive`는 **예시**예요. 내 값으로 바꿔 읽어 주세요.

### 바꿀 수 있는 값

| 값 이름 | 뜻 | 안 바꾸면 |
|---|---|---|
| `BOTSHELF_DATA_DIR` | 자료 폴더 위치. NAS·Portainer에서는 전체 경로를 적어요 | 설치 폴더 안의 `data` |
| `BOTSHELF_BIND_IP` | 어느 주소로 열지 | `127.0.0.1` (그 기기 안에서만) |
| `BOTSHELF_PORT` | 포트 | `8391` |
| `BOTKIVE_LINK_ORIGIN` | PocketRisu 연동용 봇카이브 도메인(리버스 프록시 주소). `https://`는 안 적어도 돼요 | 비어 있음 → 연동만 꺼져요 |
| `TZ` | 시간대 | `Asia/Seoul` |

`BOTSHELF_BIND_IP`에 `0.0.0.0`(모든 주소)은 넣지 마세요. 봇카이브가 인터넷 쪽으로도 열릴 수 있어요.

자료 폴더 권한은 켤 때 폴더 주인에 맞춰 자동으로 맞춰요. 로그에 `[시작] 1026:100 사용자로 켜요`처럼 나오면 정상이에요.

### 옛 봇카이브가 있다면 먼저

1. **옛 `data` 폴더를 지우지 마세요.** 다른 곳에 통째로 복사해 두면 더 안전해요. 이 복사본은 GitHub 같은 곳에 올리지 마세요.
2. 옛 컨테이너가 켜져 있으면 포트 8391이 겹쳐요. 옛 컨테이너를 **중지**만 해요. 지우지 않아도 돼요.

### Synology Container Manager

DSM 7.2 이상에 **Container Manager** 패키지가 깔려 있어야 해요.

**1. 파일 받기**

1. PC 브라우저로 `https://github.com/Hotarubiz/borkive_fork/archive/refs/heads/main.zip`을 열어 ZIP을 받아요.
2. DSM → **File Station** → `docker` 공유 폴더에 ZIP을 끌어다 놓아요.
3. ZIP을 오른쪽 클릭 → **압축 풀기** → **여기에 압축 풀기**.
4. 새로 생긴 폴더(`borkive_fork-main`)의 이름을 `botkive`로 바꿔요.
5. `botkive` 안에 새 폴더 `data`를 만들어요. 여기에 서재 자료가 쌓여요.

**2. 프로젝트 만들기**

1. **Container Manager** → **프로젝트** → **생성**.
2. 프로젝트 이름은 `botkive`, 경로는 `docker/botkive`, 원본은 **기존 docker-compose.yml 사용**을 골라요.
3. 화면에 나오는 docker-compose.yml에서 **필요한 줄만** 고쳐요. `${이름:-값}`에서 **`:-` 뒤의 값만** 바꾸고, 따옴표·괄호·콜론은 지우지 마세요.
   - DSM 역방향 프록시를 쓴다면 `ports` 줄의 `127.0.0.1`을 **프록시의 대상 IP**로 바꿔요.
     ```yaml
     - "${BOTSHELF_BIND_IP:-192.168.0.10}:${BOTSHELF_PORT:-8391}:8391"
     ```
   - PocketRisu 연동을 쓴다면 내 봇카이브 **도메인만** 넣어요. 프록시 포트가 443이 아닐 때만 `:8443`처럼 포트를 붙여요.
     ```yaml
     - BOTKIVE_LINK_ORIGIN=${BOTKIVE_LINK_ORIGIN:-botkive.example.com}
     ```
4. **다음** → 웹 포털 설정(Web Station)은 설정하지 않고 **다음** → **완료**. 처음에는 이미지를 만드느라 3~10분쯤 걸려요.

**3. 확인**

| 어디서 | 정상이면 |
|---|---|
| **컨테이너** | `botkive`가 **실행 중**(조금 지나면 '정상') |
| `botkive` → **로그** | `[시작] …사용자로 켜요`, `봇카이브 http://0.0.0.0:8391` |
| 연동을 켰다면 로그 | `PocketRisu 연동 켜짐 · 공개 주소 https://botkive.example.com …` |
| File Station → `botkive/data` | `botshelf.db`, `media`, `backups` 등이 생겼어요 |

**4. 업데이트**

1. 새 ZIP을 받아 `docker` 폴더에 **다른 이름으로**(예: `botkive-new`) 풀어요.
2. `botkive-new` 안의 `app` 폴더, `docker` 폴더, `Dockerfile.link`, `requirements-secure-link.lock`을 `botkive`에 **덮어써요.** `data` 폴더는 절대 덮어쓰거나 지우지 마세요. `docker-compose.yml`은 고쳤다면 그대로 둬요.
3. **프로젝트** → `botkive` → **작업** → **빌드**.
4. 잘 되면 `botkive-new` 폴더는 지워도 돼요.

### Portainer

**1. 자료 폴더 만들기**

자료를 둘 폴더를 미리 만들고 **전체 경로**를 적어 둬요(예: `/volume1/docker/botkive/data`). Portainer에서는 전체 경로를 꼭 적어야 해요. 비워 두면 Portainer 내부의 엉뚱한 곳에 자료가 생겨요.

**2. 스택 만들기**

1. **Stacks** → **+ Add stack** → Name은 `botkive`, Build method는 **Repository**.
2. 다음처럼 넣어요. Authentication은 끈 채로 둬요.
   - Repository URL: `https://github.com/Hotarubiz/borkive_fork`
   - Repository reference: `refs/heads/main`
   - Compose path: `docker-compose.yml`
3. **Environment variables**에 다음을 넣어요.

   | name | value | 꼭? |
   |---|---|---|
   | `BOTSHELF_DATA_DIR` | `/volume1/docker/botkive/data` | **꼭** |
   | `BOTSHELF_BIND_IP` | DSM 프록시 대상 IP, 예: `192.168.0.10` | 프록시를 쓸 때만 |
   | `BOTKIVE_LINK_ORIGIN` | `botkive.example.com` | PocketRisu 연동을 쓸 때만 |

4. **Deploy the stack**. 처음에는 3~10분쯤 걸려요. **Containers**에서 `botkive`가 `running`(조금 지나면 `healthy`)이면 정상이에요.

**3. 업데이트**

**Stacks** → `botkive` → **Pull and redeploy**(또는 **Update the stack**). `BOTSHELF_DATA_DIR`가 같으면 자료는 그대로예요.

### 도커

[Docker Desktop](https://www.docker.com/products/docker-desktop/)(윈도우·맥)이나 도커(리눅스)가 있으면 돼요.

```bash
git clone https://github.com/Hotarubiz/borkive_fork.git botkive
cd botkive
mkdir data
docker compose up -d
```

브라우저에서 **http://127.0.0.1:8391** 을 여세요. 값을 바꾸려면 `.env.example`을 `.env`로 복사해서 고쳐요.

업데이트:

```bash
git pull
docker compose up -d --build
```

### 파이썬

파이썬 3.12 이상만 있으면 돼요. 따로 설치할 패키지는 없어요. PocketRisu 연동은 도커 방법에서만 켜져요.

```bash
# 맥·리눅스
cd botkive/app
DATA_DIR=../data python3 server.py
```

```powershell
# 윈도우 PowerShell
cd botkive\app
$env:DATA_DIR = "..\data"; python server.py
```

브라우저에서 **http://127.0.0.1:8391** 을 여세요. 창을 닫으면 앱도 꺼져요. 업데이트는 `git pull` 뒤 껐다가 다시 켜요.

### LLM에게 맡기기

Claude Code, Codex, Cursor 같은 코딩 LLM에게 아래처럼 부탁하세요. [AGENTS.md](AGENTS.md)에 LLM이 따라 할 설치 순서가 적혀 있어요. NAS 주소·비밀번호·페어링 코드는 알려 줄 필요가 없어요.

```
https://github.com/Hotarubiz/borkive_fork 를 받아서 AGENTS.md의 '설치 맡기기' 순서대로 봇카이브를 설치해 줘.
내 컴퓨터는 윈도우야. 다 되면 브라우저로 열 주소를 알려 줘.
```

## PocketRisu 연동

PocketRisu에서 캐릭터를 골라 봇카이브 서재에 등록해요. `BOTKIVE_LINK_ORIGIN`을 넣고 켜면 쓸 수 있어요. **봇카이브와 플러그인은 같이 업데이트하세요.**

### 1. 플러그인 설치

1. [플러그인 저장소](https://github.com/Hotarubiz/botkive-risu-Link-plugin)에서 `dist/botkive-link.js`를 받아요.
2. PocketRisu 플러그인 설정에서 이 파일을 추가해요. 같은 이름의 이전 판은 새 파일로 바뀌어요.
3. 플러그인은 열기만 해서는 아무 데도 접속하지 않아요.

### 2. 페어링 코드 만들기

1. 봇카이브 화면의 **PocketRisu 연결** 단추를 눌러요. 홈과 휴대폰은 위쪽 막대, 다른 화면은 왼쪽 목차 아래에 있어요. 주소창에 `https://botkive.example.com/pairing`을 쳐도 돼요.
2. 봇카이브 비밀번호를 확인하면 코드를 만들고 폐기할 수 있어요. 창을 닫았다 다시 열면 비밀번호를 다시 물어요.
3. **새 페어링 코드 만들기**에서 이렇게 넣어요.
   - 연결 이름: 구분용(예: `내 PocketRisu`)
   - PocketRisu 출처 식별자: 영문·숫자·`_`·`-` 16~80자. **같은 PocketRisu에는 늘 같은 값을 쓰세요.** 바꾸면 같은 캐릭터가 한 번 더 등록될 수 있어요.
   - 권한: 등록하려면 **읽기·등록 준비·등록 모두**
4. 코드는 **한 번만** 보여요. 복사해서 플러그인에 붙여 넣어요.
5. 코드를 잃었거나 샌 것 같으면 목록에서 **폐기**하고 새로 만들어요.

### 3. 캐릭터 등록

1. PocketRisu의 **요청 로그 기능은 꺼 두세요.** 플러그인 메뉴에서 **봇카이브 등록**을 열어요.
2. **봇카이브 연결**에 도메인과 코드를 넣고 **형식 확인** → **연결 확인**. 키 식별자가 봇카이브 목록과 같은지 봐요.
3. **캐릭터 목록 조회** → 캐릭터를 골라요. **처음에는 1개만** 시험해 보세요.
4. **선택한 캐릭터 등록…** → 확인 화면을 읽고 체크 → **등록 시작**.
5. 봇카이브에서 이름·설명·로어북·이미지·에셋을 확인하고, 괜찮으면 나머지를 보내요.

**보내는 것:** 캐릭터 글(이름·설명·성격·시나리오·첫 메시지·예시 대화·제작자 노트·시스템 프롬프트 등), 대체 인사말·태그, 로어북과 그 설정, 표시용 정규식, 대표 이미지와 카드에 적힌 에셋(표정·추가 에셋).

**보내지 않는 것:** 채팅 기록, 개인 설정·API 키·로그인 정보·쿠키, 다른 캐릭터와 모듈 전체, 카드에 적히지 않은 파일, 트리거 스크립트·음성 설정·배경 HTML.

- PocketRisu 원본은 읽기만 하고 바꾸지 않아요. 봇카이브에 있던 캐릭터를 덮어쓰거나 지우지 않아요.
- 이미 등록한 캐릭터는 다시 고를 수 없어요. 봇카이브에서 지우면 다시 보낼 수 있어요.
- PocketRisu 폴더는 서재 폴더로 따라와요. 폴더가 없으면 `받은 봇`에 들어가요.
- 형식이 다른 값(빈 로어북 순서 등)은 맞춰서 보내고 확인 화면의 경고에 알려요.
- **중단:** 아직 보내지 않은 캐릭터는 보내지 않아요. 등록 요청을 이미 보낸 캐릭터는 서버에서 끝날 수 있어요. 등록된 캐릭터는 지우지 않아요.

### 보내면서 다른 일 하기

- **－(최소화)** 단추를 누르면 창만 숨고 전송은 계속돼요. 전송 중에는 X·닫기·Esc도 최소화로 동작해요. 멈추려면 **등록 중단**을 누르세요.
- 다시 열 때는 채팅 화면의 떠 있는 **📚 단추**나 햄버거 메뉴 항목을 누르세요.
- PocketRisu를 새로 고치거나 닫으면 전송이 멈춰요. 휴대폰에서 다른 앱으로 넘어가도 멈출 수 있어요. 전송 중에 캐릭터를 추가·삭제하면 뒤 캐릭터가 '목록이 바뀜'으로 실패할 수 있어요.

### 페어링 코드 기억하기 (선택)

연결 설정의 **이 브라우저에 코드 기억하기**를 켜면 인증에 성공한 코드를 그 기기의 브라우저에 저장하고, 다음에 열 때 자동으로 연결을 확인해요. **이 저장 공간은 다른 플러그인도 읽을 수 있어요.** 믿는 플러그인만 쓸 때 켜고, 필요 없으면 **기억한 코드 지우기**를 누르세요.

### 보낼 수 있는 크기

| 항목 | 한도 |
|---|---|
| 파일(에셋) 하나 | 64MB |
| 캐릭터 하나의 에셋 합계 | 1GB |
| 캐릭터 하나의 에셋 개수 | 6144개 |
| 요청 하나 | 8MB. 막히면 플러그인이 4MB → 1MB → 256KB로 줄여요 |
| 시작 요청(캐릭터 글·로어북·에셋 이름) | 32MB. 나눌 수 없어서 프록시가 막으면 '너무 큼'으로 실패해요 |

- 한도를 넘는 캐릭터는 **그 캐릭터만** 실패로 두고 다음 캐릭터를 계속 보내요.
- NAS에는 캐릭터 크기의 **약 2배**가 쓰여요. 봇을 지워도 수신함의 카드 사본은 남아요. 2GB보다 적게 남게 되면 **멈추고** 남은 캐릭터는 보내지 않아요.
- 컨테이너 메모리 상한은 **4GB**예요. 평소에 이만큼 차지하지는 않아요. NAS 메모리가 적으면 `docker-compose.yml`의 `memory` 값을 낮춰도 돼요.

### PocketRisu도 같은 NAS(도커)에서 돌린다면

플러그인 요청은 **PocketRisu 컨테이너**가 대신 봇카이브로 보내요. 그래서 그 컨테이너에서 봇카이브까지 길이 열려 있어야 해요.

1. **DSM 방화벽에 도커 대역 허용:** 제어판 → 보안 → 방화벽 → 규칙 편집 → 생성. 포트 **모두**, 소스 IP **서브넷** `172.16.0.0` / `255.240.0.0`, 작업 **허용**. 이 규칙을 **맨 위**로 올리고 저장해요.
2. **리버스 프록시 액세스 제어 프로파일에 도커 대역 허용**(프로파일을 붙였다면): 제어판 → 로그인 포털 → 고급 → 액세스 제어 프로파일 → 편집 → 생성: `172.16.0.0/12` **허용**.
3. **PocketRisu 컨테이너가 봇카이브 도메인을 NAS로 바로 찾게:** Portainer → Containers → PocketRisu → Duplicate/Edit → Network → **Hosts file entries**에 넣고 Deploy → Replace.
   ```
   botkive.example.com:192.168.0.10
   ```
   `192.168.0.10`은 DSM 프록시 **대상**과 같은 NAS 내부 IP예요. DNS 칸은 비워 두세요.

**확인:** PocketRisu 컨테이너 → Console(`/bin/sh`)에서 실행해요.

```bash
node -e "fetch('https://botkive.example.com/api/link/v4/snapshot').then(async r=>console.log(r.status,(await r.text()).slice(0,80))).catch(e=>console.log(e.cause||e))"
```

`405 {"error": "지원하지 않는 요청"}`이 나오면 길이 열린 거예요.

| 그 명령에서 보이는 것 | 할 일 |
|---|---|
| `EAI_AGAIN` | 컨테이너 DNS가 막혔어요 → 1번 |
| `403` + HTML | DSM이 막았어요 → 2번 |
| HTML(DSM 기본 페이지) | 3번의 IP가 프록시 대상과 다르거나, 공유기가 바깥 443을 NAS의 다른 포트로 넘겨요 |
| `ETIMEDOUT`·`ECONNREFUSED` | 1번을 보거나 봇카이브 컨테이너가 켜져 있는지 봐요 |

## 휴대폰 같은 다른 기기에서 쓰기

**[Tailscale](https://tailscale.com/)로 내 기기끼리만** 여는 걸 추천해요. 앱이 켜진 컴퓨터와 휴대폰에 Tailscale을 깔고 같은 계정으로 로그인한 뒤, 앱이 켜진 컴퓨터에서:

```bash
tailscale serve --bg --https=8443 http://127.0.0.1:8391
```

그러면 내 기기에서만 `https://<컴퓨터 이름>.<tailnet 이름>.ts.net:8443` 으로 들어갈 수 있어요.

**DSM 역방향 프록시**를 쓴다면 설치할 때 `BOTSHELF_BIND_IP`를 프록시 대상 IP로 맞추면 원래 쓰던 주소로 열려요. 프록시 대상을 `localhost`로 적었다면 `127.0.0.1`로 바꿔 보세요. 이때는 `BOTSHELF_BIND_IP`를 바꾸지 않아도 돼요.

내부 IP로 열면 같은 공유기의 다른 기기도 `http://192.168.0.10:8391`로 들어올 수 있어요. **설정 → 잠금**에서 비밀번호를 정해 두세요.

이런 건 **하지 마세요.** 모두 아무나 들어올 수 있게 돼요.
- 공유기 포트포워딩
- `tailscale funnel`
- ngrok·cloudflared 같은 공개 터널
- `HOST=0.0.0.0`으로 바로 띄우기

## 잠금 (비밀번호)

**설정 → 잠금**에서 비밀번호를 정하고, 언제 물을지 골라요.

| 모드 | 동작 |
|---|---|
| 끔 (기본) | 비밀번호를 묻지 않아요 |
| 밖에서만 | 이 컴퓨터에서 바로 열 땐 그냥 들어가고, 휴대폰·다른 기기(Tailscale·같은 와이파이)로 들어오면 물어요 |
| 항상 | 어디서 열든 물어요. 같이 쓰는 컴퓨터라면 이걸로 하세요 |

- 로그인하면 그 브라우저에서 30일 동안 기억해요. 비밀번호를 바꾸면 다른 기기의 로그인은 모두 풀려요.
- 비밀번호를 5분 안에 5번 틀리면 잠깐 막혀요.
- 다른 기기에서 쓸 때는 **Tailscale + 잠금 '밖에서만'** 조합을 추천해요.
- 잠가도 공개 인터넷에 여는 건 권하지 않아요. 앱 자체에 HTTPS가 없고, 혼자 쓰려고 만든 서버예요.

**비밀번호를 잊었을 때**
- 도커: `.env`에 `BOTSHELF_RESET_AUTH=1`을 넣고 `docker compose up -d` → 잠금이 풀려요. 풀린 뒤 그 줄을 비우고 다시 `docker compose up -d`.
- NAS·Portainer: `BOTSHELF_RESET_AUTH`에 `1`을 넣고 다시 배포 → 풀리면 값을 비우고 다시 배포.
- 파이썬: `RESET_AUTH=1`을 붙여 한 번 켜고(`RESET_AUTH=1 DATA_DIR=../data python3 server.py`), 다음부터는 빼고 켜요.

## 자료는 어디에

모두 `data` 폴더에 있어요.

| 위치 | 내용 |
|---|---|
| `data/botshelf.db` | 봇·채팅 로그·소개글·메모 (SQLite) |
| `data/bots/0012/` | 봇 하나의 원본 파일. `v37/` 같은 버전 폴더 안에 올린 이름 그대로 있어요 |
| `data/bots/0012/info.txt` | 그 봇의 이름·상태·태그·폴더·버전 목록 (사람이 읽는 메모) |
| `data/items/` | 자료함 자료 (봇과 같은 모양) |
| `data/media/` | 표지, 소개글 그림, 장면 그림, 그림체 견본, 페르소나 그림 |
| `data/personas/0003/` · `data/personas/g0002/` | 페르소나 자료실 원본 (버전 자료 · 폴더 공통 자료) |
| `data/backups/` | 자동 백업 (하루 하나, 30일치) |

원본 파일은 올린 그대로라 봇카이브 없이도 리스에 바로 넣을 수 있어요. PocketRisu에서 등록한 카드는 받을 때 `봇 이름.charx`로 받아져요.

**옮기거나 따로 보관하기:** 앱을 끄고 `data` 폴더를 통째로 복사하세요. 새 곳에서 같은 자리에 두고 켜면 그대로 이어져요. 자동 백업은 같은 디스크에 생기니, 가끔은 다른 디스크나 클라우드에도 복사해 두세요.

**전부 내보내기:** **설정 → 내보내기 · 들이기**(홈에서는 맨 아래에도 있어요)에서 **내려받기**를 누르면 `봇/폴더/봇 이름/버전 이름/` 모양의 압축 파일 하나로 받아요. 채팅 로그는 리스 형식(.json), 그림체는 프롬프트 글 파일과 견본 그림이 함께 들어 있고, 갤러리는 그림체 폴더 아래 `갤러리/`에 있어요. 페르소나는 `페르소나/<분류>/<폴더>/<버전>/`(갤러리는 폴더 아래 `갤러리/`)에 프롬프트 글 파일 · 그림 · 모듈로 들어 있고(버전이 하나면 폴더 바로 아래), PNG 그림은 리스의 페르소나 불러오기로 바로 넣을 수 있어요.

**폴더째 들이기:** **봇 들이기** 창에서 **폴더째 들이기**를 누르거나 폴더를 끌어다 놓으면, 컴퓨터에 봇별로 모아 둔 폴더(카드 · 모듈 · 채팅 로그 · 메모)를 한꺼번에 들여요. 카드 이름이 같으면 한 봇(카드 여러 장 = 버전)으로 묶고, 나머지 파일은 가장 가까운 봇 폴더로 붙여요. 들이기 전에 미리보기에서 잘못 묶인 파일을 옮기거나 두 봇을 합칠 수 있고, 폴더 이름이 봇카이브 폴더 이름과 같으면 그 폴더를 미리 골라 둬요. 서재에 같은 이름의 봇이 있으면 거기에 더하고, 이미 있는 파일 · 로그는 건너뛰어요. 들인 봇은 **정리 전**에 모이니, 거기서 하나씩(또는 여러 개 골라 한꺼번에) 폴더 · 상태 · 태그를 정하고 **정리 끝**을 누르세요.

**아카 글 붙여넣기:** **봇 들이기** 창의 세 번째 탭에 아카라이브 봇 글을 붙여넣으면(글 화면에서 Ctrl+A → Ctrl+C), 글 속 랠름 · 구글 드라이브 · 드롭박스 · 픽셀드레인 · 깃허브 링크와 카드 파일 링크를 찾아 받아요(zip은 풀어서 안을 봐요). 아카 자체 링크·그림은 빼고, 그림 주소(png·jpg) 링크는 꺼 둔 채로 보여 줘요(카드 그림이면 켜서 받기). 받은 파일은 새 봇으로, 또는 서재에 같은 이름의 봇이 있으면 그 봇의 새 버전으로 들이고, 붙여넣은 글은 그 버전의 소개글로, 받은 곳 링크(메가처럼 직접 받아야 하는 곳 포함)는 주요 링크로 보관해요. 프로톤 드라이브·메가 공개 링크도 받아요(링크 `#` 뒤 열쇠로 브라우저에서 풀어요 — 프로톤은 프로톤이 공개한 드라이브 SDK를 써요). 메가 폴더 링크는 링크만 보관해요.

**페르소나 · 그림체의 아카 글:** 페르소나 폴더와 그림체 페이지에도 **아카 글** 탭이 있어요. 봇 소개글처럼 아카 글을 붙여넣어 여러 개 보관해요(페르소나는 폴더 공통, 그림체는 변형 공통). 그림은 받아서 보관하고, 전부 내보내기·들이기에도 들어가요.

**들이기:** 같은 창에서 받아 둔 압축 파일을 고르면 이 서재에 더해요. 폴더 · 상태 · 태그 · 버전 · 소개글 · 채팅 로그 · 그림체 · 페르소나까지 그대로 들어오고, 이름과 만든 사람이 같은 봇은 건너뛰어요. 큰 파일은 조각으로 올리니 끊기면 같은 파일을 다시 고르면 이어서 올려요. 올린 압축 파일과 풀어 넣은 파일이 잠깐 같이 있으니 빈자리가 압축 파일의 두 배쯤 필요해요.

## 업데이트할 때 알아 둘 것

업데이트 방법은 [설치](#설치)의 내 환경 항목에 있어요. 내 자료(`data`)는 지우지 않아요. 새 기능에 필요한 칸은 켤 때 알아서 더해지고, 바뀌기 전 목록은 `data/backups`에 `pre-…` 이름으로 남겨요.

**2026년 11월 이전에 설치했다면:** 업데이트 뒤 처음 켤 때 원본 파일이 `data/files`(무작위 이름)에서 `data/bots/0012/…`(봇마다 폴더, 원래 이름)로 한 번 옮겨져요. 저절로 되고, 중간에 꺼져도 다음에 켤 때 마저 옮겨요. 옮긴 뒤에는 예전 버전으로 되돌리면 파일을 못 찾으니 되돌리지 마세요.

## 막힐 때

| 보이는 것 | 이렇게 해요 |
|---|---|
| `port is already allocated` | 옛 봇카이브 컨테이너가 켜져 있어요 → 그 컨테이너를 **중지** |
| `container name "/botkive" is already in use` | 전에 만든 컨테이너가 남아 있어요 → 중지하고 지우거나, 그 프로젝트를 다시 빌드 |
| `PermissionError` / `unable to open database file` | 로그의 `[시작]` 줄을 봐요. 보통 자동으로 맞춰져요 |
| `…로는 자료 폴더에 쓸 수 없어 root로 켜요` | 공유 폴더 권한 때문에 관리자 권한으로 켰어요. **정상으로 써요.** 바꾸려면 File Station → `data` → **속성 → 권한**에서 내 계정에 읽기/쓰기를 주고 다시 배포해요 |
| `PUID·PGID(…)로는 자료 폴더에 쓸 수 없어요` | `BOTSHELF_UID`·`BOTSHELF_GID`를 지우면 자동으로 골라요 |
| 빌드가 `pip`·`hash` 오류로 실패 | NAS가 인터넷에 닿는지 확인하고 다시 빌드해요 |
| 브라우저가 502·연결 실패 | 프록시의 대상 IP:포트와 `BOTSHELF_BIND_IP`:`BOTSHELF_PORT`가 같은지, 컨테이너가 켜져 있는지 봐요 |
| `/pairing`이 404 | 연동이 꺼져 있어요 → 로그의 `PocketRisu 연동을 켜지 않았어요:` 다음 이유를 봐요 |
| 자료가 엉뚱한 곳에 생김 | `BOTSHELF_DATA_DIR`를 전체 경로로 넣었는지 확인해요 |
| 플러그인 '연결 확인'이 인증 실패·중계 오류·HTTP 500 | 코드·주소가 맞다면 [PocketRisu → 봇카이브 길](#pocketrisu도-같은-nas도커에서-돌린다면) 문제예요 |
| 플러그인에 `수신 한도가 달라요` | 플러그인이 예전 판이에요 → 봇카이브와 같이 업데이트 |
| 결과에 `요청이 거절됐어요(…)` | 봇카이브가 그 캐릭터를 받지 않은 이유가 뒤에 적혀 있어요. 그 캐릭터만 실패해요 |
| 등록 중단·'확인 필요' | 자동으로 다시 보내지 않아요. 봇카이브에서 확인 → 연결 확인 → 목록 조회 |
| 화면이 옛날 그대로 | 브라우저 새로고침 |
| 모듈 로어북·에셋이 안 보임 | `app/rpack_map.bin`이 빠졌는지 확인해요 |

**오류를 다른 사람(또는 AI)에게 보여 줄 때**

- 보여 줘도 돼요: 화면 문구, 로그의 `[시작]` 줄과 오류 줄, HTTP 상태 번호, 키 식별자
- **보여 주면 안 돼요**: `bkl4_`로 시작하는 페어링 코드, 비밀번호, 실제 NAS 주소·IP(예시 값으로 바꿔서), `data` 폴더·DB 파일, 캐릭터 본문

## 이렇게 생겼어요 (만드는 사람용)

- `app/server.py`: 파이썬 표준 라이브러리만 쓰는 서버 + SQLite. API 목록은 파일 맨 위에 있어요.
- `app/index.html`: 화면 전부가 든 파일 하나. 빌드 도구도, 프레임워크도 없어요.
- `app/link_service.py` 등: PocketRisu 연동(`botkive-link/4`). 이 부분만 `cryptography`가 필요해요.
- `Dockerfile.link`·`docker/entrypoint.py`: 도커 이미지와 시작 도우미예요.
- 고치는 규칙은 [AGENTS.md](AGENTS.md)에 있어요.
